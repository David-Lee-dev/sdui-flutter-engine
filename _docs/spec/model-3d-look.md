# model_3d look: lighting, shadow, quality (0.29.0)

User decisions 2026-11-14: add shadows (1), adjustable lighting (2) and edge/render quality (3) to `model_3d`; structure decisions delegated to main for this session ("추가하기로 한 기능들 다 추가할 때까지 작업 사이클 돌리고 …"). Playback targets 60 fps; measure on the Galaxy only. A Filament material compiler (matc) is not available: only thermion's built-in ubershader/unlit materials may be used.

Facts (thermion_dart 0.6.1 / Filament 1.77.2): `ThermionViewer.addDirectLight(DirectLight)`, `removeLight`, `setLightDirection`, `loadIbl(path, intensity)`, `rotateIbl(Matrix3)`, `setShadowsEnabled`, `setShadowType(ShadowType.PCF|VSM|DPCF|PCSS)`, `View.setAntiAliasing(msaa, fxaa, taa)`, `View.setRenderQuality(QualityLevel)`, `View.setAmbientOcclusionOptions`, `View.setColorGrading` (exposure), `ThermionAsset.setCastShadows/setReceiveShadows`, `FilamentApp.createUbershaderMaterialInstance(unlit:, alphaMode: BLEND, hasBaseColorTexture:)`, `FilamentApp.decodeImage` + `createTexture` + `Texture.setLinearImage`, `GeometryHelper.plane`, `viewer.createGeometry`. The view is transparent (`BlendMode.transparent`, clear colour alpha 0).

## Requirements
- L1 Template props on `model_3d` (all optional; absent props keep today's picture exactly: studio IBL at the source's `iblIntensity`, no direct light, no shadow, FXAA):
  - `lighting` map: `environment` (number, default 1) multiplies the image-based light; `environment_rotation` (degrees around the vertical axis, default 0); `light` (map or `false`, default none) adds one directional key light `{ yaw, pitch, intensity, color }` — yaw/pitch in degrees in the same frame as `camera` (light comes *from* that direction), `intensity` a multiplier of a renderer default sun (default 1), `color` a colour value (default white).
  - `shadow`: `none` (default) | `contact` | `cast`. `contact` draws a soft dark ellipse on the ground under the model (works on the transparent background, follows the camera like geometry). `cast` makes the key light cast real shadows (models cast and receive; the model's own surfaces self-shadow) and also draws the contact shadow; without a `light` it behaves as `contact`. Optional map form `{ type, opacity }` with `opacity` 0–1 (default 0.5) for the contact ellipse.
  - `quality`: `low` | `medium` (default) | `high`. low = FXAA, low render quality, no ambient occlusion; medium = FXAA + medium render quality (today's look); high = MSAA 4x + FXAA, high render quality, screen-space ambient occlusion, soft shadows (PCSS or DPCF when `cast`).
  - `exposure` (number of stops, default 0) brightens/darkens the whole picture.
  - Changing any of these at runtime updates the picture without reloading the model (no `src` reload, no poster flash).
- L2 Contract: the optional exported `Model3dLookController` declares `void setLook(Model3dLook look);`; an engine-internal extension dispatches only when supported (existing 0.28 implements-based controllers remain unaffected) with an immutable renderer-agnostic `Model3dLook` (+ light/shadow/quality value types) exported from `package:sdui_engine/sdui_engine.dart`. The engine calls it right after creation and on every change, before and after `initialize` (renderer keeps the latest value and applies it once loaded), like `setCamera`.
- L3 Declare-only feature `model_3d_look_v1` (older engines ignore the props), documented in `docs/concepts.md` like `progress_stroke_cap_v1`.
- L4 Renderer (`sdui_model_filament`): applies every `Model3dLook` field with the facts above; the contact ellipse is a ground quad at the model's lowest point using an unlit, alpha-blended ubershader with a bundled radial-gradient texture (a small PNG asset generated once and committed, with its generator command documented). A look change must `touch` the render gate. Resources (lights, quad, texture, material instances) are released with the viewer.
- L5 Docs: `docs/widgets/custom/model_3d.md`, the widget doc comment, renderer README; engine CHANGELOG `## 0.29.0` and renderer CHANGELOG `## 0.3.0` (unreleased). Do not publish.

## Tests
Engine (`test/src/runtime/widget/catalog/model_3d_look_test.dart`, fake controller): absent props → one `setLook` with the default look; each prop parses to the expected `Model3dLook` (including `light: false`, shadow string and map forms, invalid values fall back to defaults); a prop change calls `setLook` again without a reload; `model_3d_look_v1` is accepted in `_requires` and not required.
Renderer (fake viewer): default look issues no direct light, no shadow, FXAA; `light` adds one direct light with the mapped direction and removes it when cleared; `shadow: cast` enables shadows and cast/receive; `contact` creates the ground quad once and reuses it; `quality` maps to the AA/render-quality/AO calls; `exposure` sets colour grading; a look change while loading applies once loaded; dispose releases the light and quad.
Device (Galaxy Z Flip6 bench): RobotExpressive and Xbot play at 60 fps with `quality: medium` + `shadow: contact` and with `quality: high` + `shadow: cast` + light; record CPU/GPU/PSS against the frame-rate baseline.

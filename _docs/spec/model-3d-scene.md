# model_3d scene and camera target (0.29.0)

User decisions 2026-11-14: a character must stand on a planet-like ground in one view (11), and the camera must close up on a part (face) and pan (10). Ground and character are separate GLBs (recommended earlier: swap and cache independently). Walking on a small planet is done by spinning the planet under a character playing a walk clip, not by moving the character. Structure decisions delegated to main for this session.

## Requirements
- S1 `model_3d` gains optional `scene`: a list of extra models shown in the same view with the primary `src` model: `{ src, position: [x, y, z], rotation: { yaw, pitch, roll }, scale, clip, spin: { axis: x|y|z, speed } }`. `clip` loops that model's own animation; `spin` rotates it continuously at `speed` degrees per second about its own origin. All values are in the primary model's glTF units (metres as exported from Blender), so a scene authored in one Blender file lines up.
- S2 The renderer already keeps every model at its glTF transforms and frames with the camera around the primary model's GLB-derived world extent (model-3d-world-bounds.md). Extras are placed in that same world space; the camera frames the primary model only, so extras may extend outside the frame.
- S2b Framing fix (device finding 2026-11-14): `zoom: 1` must fit the whole primary model. Use its bounding sphere (half the diagonal of the world extent) instead of half the largest edge × 1.15, so wide or boxy models (RobotExpressive's hands and head, AnimatedMorphCube) are not cut; tall/deep models such as Fox keep roughly today's picture.
- S3 Extras load independently through the same byte/disk cache; one failing extra is logged and skipped (the primary still shows); `on_ready` waits for the primary only. Changing an extra's `position`/`rotation`/`scale`/`spin`/`clip` updates it without reloading; changing its `src` reloads only that extra. Extras cast/receive shadows and use the same `lighting` as the primary.
- S4 `camera` gains `target`: `[x, y, z]` (primary model units) or a node name in the primary model (e.g. a head bone/node); default is the primary model's bounding-box centre. Changing `target` eases like the rest of `camera` over `duration`; `zoom` is relative to the framed distance as today. A missing node name falls back to the default centre.
- S5 `controls.pan: true` lets a two-finger drag move the target in the view plane (bounded by `max_pan`, default 0.5 of the framed size); `return_duration` eases the pan back like rotation.
- S6 Contract: the optional exported `Model3dSceneController` declares `void setScene(List<Model3dSceneItem> scene, {bool active = true});` and receives immutable scene snapshots before/after initialize and on changes. Engine-internal dispatch is a no-op without the capability. `Model3dRequest` carries only the primary `src`; `Model3dCamera` carries `target` (`Model3dTarget`: point, node or flattened blend during easing) and `pan`. Existing implements-based controllers need no optional members.
- S7 Declare-only feature `model_3d_scene_v1` (older engines ignore `scene`, `target`, `pan`).
- S8 Docs: widget doc comment, `docs/widgets/custom/model_3d.md`, renderer README, CHANGELOG entries (unreleased 0.29.0 / 0.3.0). Do not publish.

## Tests
Engine (fake controller): `scene` parses into items (invalid entries dropped); item changes call the scene update without reloading the primary; `camera.target` point and node forms parse and ease; two-finger pan moves the camera's pan within `max_pan` and returns after release; absent props keep today's calls.
Renderer (fake viewer): with `scene` the primary is not unit-cube transformed; each extra loads, gets its transform, loops its clip, spins (transform updates while spinning keep the render gate held); a failed extra does not fail initialize; changing an extra's transform does not reload it; `src` change reloads only it; node target resolves to the node's world position; dispose destroys extras.
Device: Xbot standing on a sphere-like planet GLB with `spin` + walk clip at 60 fps; record CPU/GPU/PSS.

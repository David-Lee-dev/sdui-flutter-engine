# model_3d removal and structural refactor before 0.29.0 / renderer 0.3.0

User decisions 2026-11-15: toon and shading are treated as impossible with thermion 0.6.1 built-in materials, and "if it cannot be done perfectly, do not do it". Remove `shading`, `outline` and `highlight_on_tap` entirely; keep `on_tap_model`. Get the change reviewed by at least two independent sessions for whether it keeps the existing SDUI engine structure and is maintainable, and refactor as needed. Structure decisions are delegated to main for this session.

Two independent structural reviews (Codex, Claude; 2026-11-15) both returned `refactor` with these agreed findings. Behaviour of every remaining feature must stay exactly as accepted (frame rate, look, world bounds framing, scene/camera target/pan, outfit, expressions/look-at/layer, tap, reuse/warm-up/prefetch); existing tests are the safety net and must keep passing except tests of removed features.

## Requirements
- RF1 Removal: delete `Model3dShading`, `Model3dOutline`, `Model3dTapHighlight`, `Model3dLook.shading/outline`, `setTapHighlight` (capability and extension), the `model_3d_shading_v1` feature, widget parsing/doc of `shading`/`outline`/`highlight_on_tap`, all renderer unlit/outline/highlight code and its tests, and every doc/spec/CHANGELOG/README mention (the tap-shading spec keeps only P1 tap and records the removal decision). Stop requesting accessible geometry buffers at load (they existed only for outlines; picking uses entity ids), in warm-up, primary, reuse and prefetch paths.
- RF2 Contract consistency: `setLook` moves off the base `SduiModel3dController` into a `Model3dLookController` capability with the same extension dispatch as scene/outfit/motion/tap, so classes that `implements` the 0.28 controller keep compiling (a test proves it). `Model3dLookAt.target` becomes an enum (camera, pointer, point) instead of a free string. All capability extensions use one dispatch style. The public barrel exports value types and capability interfaces; the dispatch extensions stay engine-internal unless a renderer needs them.
- RF3 Engine widget: `model_3d_widget.dart` keeps lifecycle, controller generations, state machine, progress glue, visibility/retry, pointer handling and action dispatch. Pure template parsing moves out by reason to change: look/scene/outfit/state-table parsers to `model_3d_props.dart`; look_at/layer/morph/blink parsing beside the expressions clock in `model_3d_expressions.dart`. One shared point parser (`[x, y, z]`, built on `PropsResolver.number`) serves scene positions, camera target and look_at; duplicated finite checks go. No new layer, coordinator or global parser.
- RF4 Renderer split by reason to change, following the package's one-concern-per-library style (`model_bytes.dart`, `render_gate.dart`, `load_stats.dart`): a thin `filament_model_3d_source.dart` (source configuration, controllerFor, controller facade with load orchestration, frame hook and aggregate render hold as the OR of collaborator needs, final dispose order); serialised native lane + disposed flag + quiet runner shared by collaborators; viewer keep-alive/warm-up/prefetch pool; GLB preparation (today's misnamed `_PreparedOutfitAsset`: node identity renaming, material isolation) with a GLB chunk reader shared with `model_bounds.dart`; framing/camera placement/target resolution; look (lighting, quality, exposure, contact shadow, one defaults/reset path used by both look changes and viewer reuse); outfit; motion (base/layer pose, morphs, gaze); scene extras. Collaborators receive the viewer/asset/bounds values they need, not the whole controller; native ordering and dispose safety are preserved. One sRGB→linear helper.
- RF5 Deferred fixes: a layer change that only changes `weight` keeps the playhead and retargets the weight envelope (clip/loop change still restarts); remove the redundant `_normalizedBounds`/`_KeptViewer.normalized` flag (near/far from halfExtent); cap accessor counts without a bufferView (e.g. by the GLB byte budget) and throw `FormatException` so the bounds fallback applies; compiler feature list: the remaining `model_3d_*_v1` names go after `lifecycle_exit_back_v1` under one `// 0.29.0 … Declare-only` comment; docs (`docs/concepts.md`, `docs/widgets/custom/model_3d.md`, README, CHANGELOGs) consistent and in the repo's existing section order; specs updated to the adopted capability contracts.
- RF6 Tests mirror the split: renderer fakes move to `test/support/`, renderer and widget tests are split by feature (core/lifecycle, camera/framing, look, scene, outfit, motion, tap, reuse, bounds as pure tests), named by behaviour like the rest of the repo (spec ids only in group names/comments). Order assertions stay only where order is the contract (pose composition, dispose serialisation); the frame-rate test checks only that the rate is applied after viewer creation and before first use. Revert or justify the `tester.tap` → `tester.tapAt` edits in pre-existing tests. No test-only production APIs.

## Tests
All engine tests (`fvm flutter test` at the root, including `test/architecture_boundary_test.dart`) and all renderer tests (`fvm flutter test` in `packages/sdui_model_filament`) pass; tests of removed features are deleted with them; a 0.28-style `implements SduiModel3dController` fake compiles without look/scene/outfit/motion/tap members; weight-only layer change keeps the playhead; huge zero-bufferView accessor falls back. Device (Galaxy bench `base`, `look`, `scene`, `outfit`, `motion` suites): 60 fps and CPU/GPU/PSS not worse than the pre-refactor final run (GPU and PSS should drop back once geometry buffers are no longer requested).

### Engine implementation cases
- RF-E1: On the accepted 0.29 tree, mount removed props and retain `on_tap_model`; expect the default retained look, ancestor taps without picking when only the removed highlight prop is present, and hit/miss dispatch unchanged. Compiler must reject `_requires: [model_3d_shading_v1]` and accept remaining feature declarations. Boundary: widget/compiler.
- RF-E2: Mount an actual 0.28-style implements controller with no optional members, then invoke all optional engine dispatches; expect no error/default completion count/null hit. A separate look-capable fake receives snapshots before initialization and during updates. Boundary: controller/widget.
- RF-E3: Mount camera, scene and look_at with numeric triples, numeric-string triples, malformed lengths and non-finite values; preserve numeric-only camera/scene and string-coercing look_at, defaults and rejected entries. Verify camera/pointer/point gaze enum and pointer release. Boundary: widget.
- RF-E4: Run every retained widget/compiler test plus architecture checks and the full engine suite after parsing/test moves. Expected behaviour remains unchanged; no manufactured Red for existing behaviour.
